<task type="auto">
  <name>Task 2: Fix clone_vm ovftool invocation — dest_url, --acceptAllEulas, error output</name>
  <files>esxi_mcp_server/vmware_manager.py</files>
  <action>
    The current clone_vm implementation has three bugs in its ovftool subprocess call (lines 550-576):

    Bug 1 — Wrong dest_url: Current code appends `/{new_name}` to the destination URL:
    ```python
    dest_url = (
        f"vi://{self.config.vcenter_user}:{self.config.vcenter_password}"
        f"@{self.config.esxi_host}/{new_name}"
    )
    ```
    ESXi interprets the path component as a datacenter name, which fails on standalone ESXi. The destination URL must have NO path — ovftool uses `--name` to set the clone's name:
    ```python
    dest_url = (
        f"vi://{self.config.vcenter_user}:{self.config.vcenter_password}"
        f"@{self.config.esxi_host}"
    )
    ```

    Bug 2 — Missing --acceptAllEulas: Without this flag, ovftool prompts interactively and hangs until the 600s timeout expires. Add `"--acceptAllEulas"` to the cmd list, immediately after `"--noSSLVerify"`:
    ```python
    cmd = [
        ovftool_path,
        "--noSSLVerify",
        "--acceptAllEulas",
        f"--name={new_name}",
        source_url,
        dest_url,
    ]
    ```

    Bug 3 — Empty error message: ovftool writes its error messages to stdout, not stderr. The current exception only includes `result.stderr` which is empty. Fix by combining both streams:
    ```python
    if result.returncode != 0:
        combined = (result.stdout + result.stderr).strip()
        logging.error(f"ovftool output: {combined}")
        raise Exception(f"ovftool clone failed (exit {result.returncode}): {combined}")
    ```

    Apply all three changes. Do not change the source_url, the subprocess.run() call parameters, or the TimeoutExpired handler.
  </action>
